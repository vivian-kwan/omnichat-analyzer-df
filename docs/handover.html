For the team

Nothing about how you use the panel day-to-day has moved. Here's what's different.

It can get out of your way now

A new — button next to close shrinks the panel to just its header bar, so it stops covering the chat underneath. Try it in the demo below — it remembers your choice.

Label colors changed

Quotation is now yellow, Quotation start is orange, Sales follow-up is red — a heat scale that gets warmer as a conversation moves toward closing.

New: Brand activity alert

The Brand stat box turns red when the brand has sent disproportionately more messages than the customer — a sign a chat may be getting over-pushed or the customer's gone quiet.

Settings, split up

Keyword rules, the new alert thresholds (seniors only), and your token/API key now live in three separate cards instead of one long scroll.

Summary before tagging

Chat Summary now sits above the tagging dropdown, matching the order you actually work in — read, then tag.

AI Analysis — fixed

The Analysis button (AI mode) was silently failing every time due to a bug in how the panel talked to the server. That's fixed — it now returns a real summary, price, and per-message labels.

Steps

  1. Review the diff. In the git repo (vivian-kwan/omnichat-analyzer-df), run git diff — three files are already updated in the working tree (see callout above) but nothing is staged or committed.
  2. Commit and push to main. No new env vars are needed — /api/me reuses the existing EXTENSION_SECRET check and users.json.
  3. Deploy via Cloudways. Trigger the existing "Deployment via GIT" pull (or wait for auto-deploy if configured). data/skills/*.txt and data/users.json are tracked in git — not gitignored — so they deploy automatically, no manual re-copy needed on the server.
  4. Restart the Node process. SSH in, source /home/master/.nvm/nvm.sh, then pm2 restart omnichat-server.
  5. Sanity check — hit https://api.df-creativehome.com/health, then confirm /admin/skills.html shows the new styling.
  6. Update the Chrome extension. The Plug-in/ folder isn't in this git repo. If your team runs it as "Load unpacked," just pull the latest development/Plug-in/ files locally. If it's distributed via the Chrome Web Store or a private .crx, bump the version in manifest.json and re-publish through your usual channel.
Rollback: since nothing's committed yet, rolling back the server side is just git checkout -- . before you commit. Once committed and deployed, redeploy the previous commit via Cloudways as usual.

Known gaps, not fixed this round

Plug-in/CHROMEWEBSTORE.md is stale. Its permissions justification still describes direct api.openai.com / Gemini / DeepSeek host permissions from an older architecture — the current manifest.json only requests api.df-creativehome.com and Omnichat. Worth updating before the next Web Store submission, not touched here since it wasn't part of this round's scope.
Local testing needs a temporary tweak. background.js's SERVER_BASE points at proxy.php on Cloudways. To test against a local npm run dev server, point it at http://localhost:3000/ temporarily and revert before committing.
